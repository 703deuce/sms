# Motion Studio editable elements: contract v1 (`transovo.editable-elements/1`)

Status: implemented and tested on the producer side (this repo). It supersedes the v0.1 proposal in
`/workspace/editable_contract_poc/CONTRACT.md`. JSON Schemas for every document are in `schemas/` (draft 2020-12),
generated by `tools/gen_schemas.mjs`.

## 1. Principles
1. **The production stays the production.** A scene is edited by changing declared properties only. Animation, camera,
   timing, easing and narration anchors are protected; the scene's own code renders them exactly as delivered.
2. **One resolver everywhere.** `producer/runtime/ms-resolve.js` is isomorphic. The same file runs in the editor iframe, in
   the worker's headless Chrome and in Node (job validation, dependency analysis). Preview and export cannot disagree on
   what a property means.
3. **Everything is addressed by content.** Assets `ast_…`, fonts `fnt_…[.faceIndex]`, bundles `bnd_…` are
   `prefix + sha256[:32]` of the bytes. Project versions only reference IDs, never paths.
4. **Immutable versions.** Version N is never rewritten. A deterministic edit publishes N+1 (write-once, `409` on a
   stale base). Any validation error stops the job before anything is published.
5. **No templates, no preset fonts.** Each scene declares its own elements. Any font file in the storage font index
   that the scene's engine can render is allowed.

## 2. Property tiers
| tier | who applies it | where it runs | example |
|---|---|---|---|
| `live_editable` | editor iframe, instantly; worker for export | browser runtime | text, colour, font, image, logo, focal point |
| `render_editable` | worker only (needs a render step) | worker (Python/FFmpeg/OpenCV) | portrait grade, auto focal point (face detection), shot framing/zoom in `sh04` |
| `ai_editable` | a `creative_production` job (Grokbot skill session) | not this pipeline | reveal style, composition, re-voicing, new footage |
| protected | nobody | n/a | camera path, tweens, timing, seeds, geometry, lighting |

Protected and AI-only property names are listed in the manifest (`protected[].props`, `elements[].aiEditable[].prop`) so a patch
that names them is rejected with `PROTECTED_PROPERTY` / `AI_REQUIRED`, not silently ignored.

### 3.1 Manifest (per scene)
`fixtures/keith/S01/editable-elements.json` is the complete reference. Key fields:
- `format {width, height, fps, frames, holdFrame}`, `timelinePlacement`, `engines`, `entry`.
- `livePreview`: `live` (iframe applies `live_editable` props instantly) or `render_only` (the editor shows a poster and
  asks the worker for a still via a preview job). `fallback` says which: `still_then_render`.
- `colorTokensUsed`, `fontTokensUsed`: which theme tokens the scene reads. `derivedTokens`: tokens computed from a
  theme colour with `method: "oklch-delta"`. While the source colour equals `designFrom`, the exact `designValue` is
  used, so original settings reproduce the original pixels.
- `elements[]`: `{id, label, kind, layer, timing, properties{…}, aiEditable[]}`. Property spec:
  `{tier, type: text|color|number|enum|boolean|font|image|point, default | bind: "colors.x"|"fonts.x", min, max, enum,
  maxChars, maxLines, allowEmpty, overflow: "auto_fit"|"error", fontStyle, font (name of the font prop for coverage),
  formats, minWidth, minHeight, aspect, fallbackBind, spokenInNarration}`.
- `contrast[]`: `{element, fg, bg[], fgAlpha, bgBlend, min, designBaseline}`.
- `safeArea`, `allowedOverlaps`, `fontEngine` (`browser`, `skia-python`, `pil`, `ffmpeg-drawtext`, `canvaskit`), `italicTokens`.
- `protected[]`: `{what, where, props[]}`.

### 3.2 Theme
One theme per project: `colors.<token>.value` (`#RRGGBB`), `fonts.<token> = {faces:[fontId…], weight, style?, label}`
and `brand.logo = {asset} | null`. Scenes read tokens; they never hard-code them.

### 3.3 Edit patch and resolution order
```json
{ "schema": "transovo.edit-patch/1",
  "theme":  { "colors": { "accent": { "value": "#4FD1C5" } }, "fonts": { "display": { "faces": ["fnt_97aa…"], "weight": 400 } } },
  "scenes": { "S01": { "tokens": { "colors.text": "#FFFFFF" },
                       "elements": { "location": { "text": "Central Islip, New York" }, "title": { "color": null } } } } }
```
Value of a property = element override → scene token override → (theme + theme patch) → manifest default.
`null` deletes an override. Overrides accumulate in `version.overrides`, so version N+1 = theme N + patch.

## 4. Scene runtime API (`window.__scene`)
| method | meaning |
|---|---|
| `seek(t)` | seconds; deterministic (time-driven GSAP/three.js/Pixi, seeded randomness) |
| `getProps()` | `{sceneId, overrides, resolved, hash}` |
| `validate(patch?)` | issues for the current state, or a dry run of a patch (never changes the scene) |
| `setProps(patch, {force})` | atomic. Static errors are rejected. Layout errors (overflow…) roll back to the previous state exactly. `force` shows an invalid state in the preview only; it can never be exported. Returns `{ok, rejected, stage, issues, hash, applyMs}` |
| `describe(t?)` | elements with tier/type/value/source, **screen bounds** for DOM/SVG and **projected bounds** for WebGL/Pixi objects (`space: "projected"`, `clipped`), plus issues |
| `provide({fonts, assetUrls, assets})` | the host supplies records and signed URLs for fonts or assets picked during editing |

Host payload: in a worker `window.__MS_HOST`; in the editor an `init` postMessage:
`{theme, overrides, assetUrls{id: url}, assets{id: meta}, fonts{fontId: record}, mode: "live"|"render"}`.

## 5. Validation codes
Static (resolver, runs in editor + worker): `UNKNOWN_ELEMENT`, `PROTECTED_PROPERTY`, `AI_REQUIRED`, `UNSUPPORTED_PROPERTY`,
`TIER_NOT_LIVE`, `UNKNOWN_TOKEN`, `TYPE`, `RANGE` (no silent clamping), `ENUM`, `TEXT_LINES`, `TEXT_TOO_LONG`, `TEXT_EMPTY`,
`NARRATION_MISMATCH` (warning), `FONT_MISSING`, `FONT_ENGINE_UNSUPPORTED`, `FONT_WEIGHT_UNAVAILABLE` (warning), `FONT_STYLE_UNAVAILABLE`
(warning), `GLYPH_MISSING` (per glyph, fontTools cmap of the face actually picked for weight/style), `ASSET_MISSING`, `ASSET_FORMAT`,
`SVG_UNSAFE`, `IMAGE_TOO_SMALL`, `IMAGE_CROPPED` (info), `CONTRAST_LOW` (warning below min(min, designBaseline), error below 2:1).

Layout (engine, measured in the real renderer): `TEXT_OVERFLOW` (error), `AUTOFIT_APPLIED` (info), `OVERLAP`, `OUT_OF_SAFE_AREA`,
`IMAGE_UPSCALED`, `FRAMING` (warnings).

Job: `SCHEMA`, `WRONG_MODE`, `MODE_NOT_SUPPORTED`, `NOT_EDITABLE`, `UNKNOWN_SCENE`, `NOT_THEME_AWARE` (warning), `SCENE_RUNTIME_ERROR`,
`RENDER_FAILED`, and `409 version_conflict` from storage.

## 6. Render keys and dependency analysis
- `renderKey = rk_ + sha(canon({bundleId, resolvedProps (font labels stripped), runtimeLockId}))`. The same key means the clip is reused.
- Only scenes whose key changes re-render. Non-editable scenes keep their clip and get a `NOT_THEME_AWARE` warning when the theme changes.
- `masterRenderKey = mk_ + sha(recipe, segment clip ids, theme-bound recipe values, lock)`. The master is re-assembled only when this changes.
- Each job reports, for every scene, `rerender` and the reason with the changed resolved paths, plus affected transitions and the master reason.

## 7. Runtime pins
`producer/lib/runtime-lock.mjs` records the versions of Chrome, Node, puppeteer, ffmpeg, Python, skia, Pillow, numpy, OpenCV, fontTools and
CanvasKit, plus seeds. It is stored as an asset referenced by `version.runtimeLock`, and the lock id is part of every render key.
