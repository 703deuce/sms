## Contract (producer view)

- **Webhook.** HTTPS JSON POST to `GROKBOT_WEBHOOK_URL` with `Authorization: Bearer <GROKBOT_WEBHOOK_KEY>`. Acknowledge with HTTP 2xx and work asynchronously. Idempotency is by Transovo job row, not by us starting a second render for the same `jobId`. Dispatch only happens when `GROKBOT_LIVE_MODE=1`. Token lifetime is **36 hours**. The `source.url` signed URL expires in **1 hour** — download it immediately. Never print tokens or signed URLs.
- **Two actions, one director.** `clip_and_finish` (`mode: autonomous_clipper`) watches the full source, picks and scores its own moments, and returns up to `maxClips` (1–10, default 3) finished 9:16 / 30 fps MP4s plus `highlights.json`. `finish_clip` (`mode: source_footage_enhancement`) enhances one already-scored clip (source bounds, score, editorial brief included). There is **no** `revise_clip` / `revise_video` path in this v1, and **no** `/source`, `/transcript`, or `/moments` refetch endpoints.
- **Shared payload fields.** `version: 1`, `jobId` (`caf_<uuid>`), `projectId`, `jobToken`, `jobUrl` and `callbackUrl` (same: `{origin}/api/clips/agent/jobs/{jobId}`), `title`, `source: {url, filename, mime?, startMs, endMs, durationMs}`, `aspectRatio: "9:16"`, `fps: 30`, `quality: "premium"`, `mediaPolicy: "user_footage_primary"`, `webResearch: false`, plus a long `direction` string. `clip_and_finish` also sends `maxClips` and `targetDurationsSeconds: [30, 60]`. `finish_clip` also sends `clipId`, `score`, `durationSeconds`, `projectTitle`, and source bounds that are absolute on the original upload (or 0-based if the signed URL points at a clip-local segment).
- **Callbacks** (`Authorization: Bearer {jobToken}` only):
  - `GET {jobUrl}` — job status (phase, progress, message). Does **not** re-issue a source URL or the original assignment.
  - `POST {jobUrl}/progress` — `{stage, percent?, message}`. `phase` / `progress` aliases are accepted. Invalid stages become `editing`. Percent is monotonic and clamped to ≤99 until complete.
  - `POST {jobUrl}/assets` — `{action:"prepare", kind, filename, mime, bytes}` then upload via returned `signedPut` / `tus` / `s3Multipart`, then `{action:"commit", uploadId, parts?}`. Wait for `ready`. Max 100 artifacts, 2 GB each. Filename sanitized to `[A-Za-z0-9._-]`. Kinds: `video`, `project`, `media`, `audio`. Mimes: `video/mp4`, `video/webm`, `application/json`, `image/png`, `image/jpeg`, `audio/mpeg`, `audio/wav`, `audio/mp4` (no `.srt` / `text/plain`).
  - `POST {jobUrl}/complete` — see below, or `{status:"failed"}` (server supplies customer wording).
  - There is **no** `/messages`, `/usage`, or `/parent-artifacts` on this job API.
- **Progress stages (fixed set):** `selecting`, `editing`, `graphics`, `review`, `rendering`, `delivering`, `complete`. Defaults are Transovo-voiced (“We're preparing your highlights…” etc.). Messages are sanitized: anything mentioning bots, models, engines, paths, URLs, tokens, or stack traces is replaced with the default.
- **`clip_and_finish` delivery.** Upload each finished MP4 as `kind: "video"`, `mime: "video/mp4"`, then a JSON file **named exactly `highlights.json`**, `kind: "project"`, `mime: "application/json"`, ≤2 MB, then `POST /complete` with `{status:"complete"}` (`durationMs` in the body is optional; the server sums the manifest). Manifest: `{clips:[{filename, title, startMs, endMs, durationMs, score, why}]}` (or a top-level array). `startMs`/`endMs` are **absolute** in the original source. `durationMs` is the finished MP4 length (1_000–180_000 ms). `score` is an integer 0–100. `filename` must equal a committed MP4 filename. 1–10 records. The API then creates new Clip rows (old scored clips, if any, remain). **`project.json` is not imported on this path.**
- **`finish_clip` delivery.** Upload one `video/mp4` (`kind: "video"`) and optionally `project.json` (`kind: "project"`, filename exactly `project.json`, schema `transovo.motion-project/1`, assets referenced by filename). Then `POST /complete` with `{status:"complete", durationMs}` where `durationMs` is a safe integer 1_000–600_000. The app saves the MP4 as a non-destructive preview/download (original preview key kept in `aiMeta`), and attempts to import editable layers without overwriting original dialogue. If the manifest fails, only the MP4 is delivered — do not claim timeline parity.
- **Limits and errors.** Concurrent running jobs per workspace: 6 (429). Daily creates per workspace: 30 (429). Project must be `READY` with an uploaded video (409). Webhook must be HTTPS and accept the POST within 15 s, else the job is marked `dispatch_failed` (“Producer unavailable.” / “Could not start. Please try again.”). Auth failures: 401. Finished jobs reject further progress/assets (409). Invalid highlights or missing MP4: 400. Producer-reported `{status:"failed"}` becomes a customer-safe “Your clip could not be finished. Try again.”

## Product flow and gaps in ChatGPT’s code

- Opt-in at upload (“Transovo Agent — fully finished clips”) **skips the legacy clip-finding worker** and marks the project `READY` once the file is uploaded. Automatic `clip_and_finish` dispatch is a **client `useEffect` on the project page** (`Idempotency-Key: auto-grok-{projectId}`), not a server-side queue. If the customer never opens the page, nothing is sent. Manual “Create finished clips” and “Finish selected clips” still work (manual discover uses a fresh UUID key; finish accepts 1–5 `clip_` ids).
- If auto-dispatch fails (for example the producer does not yet accept the action), the row is stored as `dispatch_failed` under that stable idempotency key. Reloading the page returns the failed job and **will not retry** automatically. The manual button can start a new job because it uses a new key.
- `GET {jobUrl}` always returns `mode: "source_footage_enhancement"`, even for `clip_and_finish` jobs, and does not echo `action`, `maxClips`, or a fresh `source.url`. If the 1-hour signed URL expires before download, there is no official refetch. `dispatchClipAgentDiscover` also does not null-check `sourceUrl` before putting it in the payload (the finish path does).
- `clip_and_finish` completion does not import `project.json` / per-clip editable timelines. `.srt` cannot be uploaded (mime not in the allow-list). No revision action yet. `assertDevApiAccess` wraps the customer POST routes; same-origin browser fetches should pass, but a missing `TRANSOVO_DEV_API_KEY` is required for that to stay open (if the env key is set, cross-site callers need `x-transovo-dev-key`).
