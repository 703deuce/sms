## 3. How rendering works now vs before

**Before (through November 19, 2026).** The Producer routine auto-submitted films to **Modal** (CPU, with fan-out). `submit.sh <JOB> cpu` packaged the film, uploaded it to Modal, and Modal rendered, QA'd, published the master and completed the job. The box path (`bg_delivery/`) was fallback when Modal was disabled or submit failed twice.

**Now (November 20–21, 2026, current).** Rendering runs on the **sms server** through a private Coolify app, `motion-render-worker`. The Producer still runs the same command:

```bash
python3 /workspace/motion_kit/modal/make_bundle.py --job-dir <J> --check-page   # until "ok": true
bash /workspace/motion_kit/modal/submit.sh <J> cpu
# then at most one: bash /workspace/motion_kit/modal/status.sh <J>
```

`submit.py` defaults to `RENDER_BACKEND=self_hosted`. The script registers the bundle with the job-scoped assets API, then calls `https://transovo.ai/api/motion-studio/agent/jobs/:id/start-render`. The web app forwards the job internally to the private worker (`motion-render:8098`). The Producer does **not** talk to the render host and does not need `RENDER_HOST_SECRET` or `RENDER_WORKER_URL`.

Modal is **disabled** (`/workspace/motion_kit/modal/.modal_disabled`, or `MODAL_DISABLED=1`). It is kept only as an explicit fallback (`RENDER_BACKEND=modal` or `MOTION_MODAL_FALLBACK=1`) and must not be used without Rick's OK. Config lives at `~/.modal.toml` (profile `transovo`); CLI at `/workspace/motion_kit/modal/venv/bin/modal`.

The producer reports `complete` to the coordinator once the render is *submitted* (the self-hosted worker, like Modal before it, finishes QA, uploads the master, publishes the editable package and completes the job). Do not call `/complete` or `approveMaster` on a live self-hosted job. Do not run `bg_delivery` at the same time as a self-hosted submit.

Expect roughly 9–10 minutes of render time per film minute on the current CPU worker. A later dedicated render server is planned; do not change this path until Rick asks.
