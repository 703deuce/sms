I think this is where the product could become really interesting, because I wouldn’t make it look like a traditional video editor when somebody first opens it.

I would make it feel like a combination of ChatGPT, a documentary production studio, and an intelligent video editor.

Someone should be able to arrive with nothing but an idea, or arrive with a script and three hours of footage, and both people should be able to use the same product.

But once a project starts, they need to see what the AI is making, control the story, inspect the motion graphics, and change anything they don’t like.

Here’s exactly how I’d design it.

I would divide this screen into four practical areas:

Left panel — Project and AI Director. The user can open the story, uploaded media, scenes, graphics and audio. They can also tell the AI to change things conversationally.

Center — Video preview. The largest area. They see their actual documentary, play it, pause it, and select graphics or clips.

Bottom — Storyboard or timeline. Beginners can use a visual storyboard. Advanced users can expand the full timeline for precise edits.

I would not make users interact with the timeline just to generate their first documentary.

4. The production workflow, from idea to finished video

I’d use six stages, but all inside the same project.

* Develop the story
    The AI researches the subject, writes a script or organizes the user’s existing narration, and proposes chapters.
    The customer can approve the story or request changes. Research-backed claims retain source links.
* Prepare the footage and assets
    The AI catalogs all uploads, identifies people and objects, transcribes interviews, finds relevant footage, and lists missing visuals.
    Users can add media or choose from properly licensed sources. The system never silently treats an arbitrary online clip as cleared for reuse.
* Direct the documentary
    The AI decides which story moments need actual video, photographs, diagrams, maps, charts, or cinematic sequences.
    It creates a master visual plan that includes transitions into and out of real footage.
* Generate motion graphics
    A coding agent uses your polished framework to create subject-specific graphics. It can invent a neural-network animation, stock-market visualization, historical timeline, or something entirely different.
    It renders frames, checks readability and motion, and fixes problems before finalizing the scene.
* Assemble and mix
    The editor combines all the footage, graphics, narration, sound effects, music, and transitions into one coherent timeline.
* Review and export
    The user watches the video, requests changes, approves it, and exports an MP4 or opens the project in the advanced editor.

There should be a useful checkpoint after the story and visual plan—but I wouldn’t force users to approve every chapter or graphic. They could select fully automatic production instead.

The editor can use ordinary cuts when they’re more appropriate. It shouldn’t force a zoom-through photograph on every transition.

7. How the user makes revisions

I’d make conversational editing the default.

AI Director

“The opening is too slow. Make the first 20 seconds more dramatic, and make the chart easier to read.”

Proposed changes

Shorten opening camera travel by 3 seconds.

Increase financial chart label sizes.

Adjust the opening impact and music timing.

Example proposed changes, not actions applied to a real project.

This eliminates a lot of the technical work for beginners, while still giving professionals access to direct editing controls.

8. What if the user has no footage at all?

The system should still be usable.

For someone entering only “Make a documentary about the history of artificial intelligence”, it would research the subject, create a script, offer narration, identify missing visual assets, and construct code-generated graphics.

But it shouldn’t pretend it can automatically access every historical image or movie clip. If it can’t find licensed footage, it can use verified archival photographs, custom illustrations, diagrams, maps and typography.

That naturally gives you two production styles within the same product:

Documentary from an idea: More research, narration and code-generated visual storytelling.

Documentary from uploaded media: More actual footage, interviews and editorial assembly, with motion graphics added where they improve the story.

9. What I would build first

Given your existing Transovo editor and the custom and Cinematic Skill experiments, I wouldn’t build all of this immediately.

I’d start with one working production workflow:

First release

* Start with a script, narration, or documentary idea.
* Upload photos and video clips.
* AI creates a chapter plan and visual storyboard.
* Cinematic engine generates maps, animated text, diagrams, charts and document treatments.
* AI assembles graphics and real footage into one timeline.
* Preview, request conversational changes, and export.

I’d initially target five-minute documentaries before attempting fully automated 30-minute productions.

One practical detail: show an estimated production cost or minute allowance before the full render. The user should know which operations are included and which might use paid third-party media or voice services. Routine code-rendered revisions shouldn’t be presented like expensive video-generation credits.

My biggest design recommendation

Don’t make the AI chat the entire interface, and don’t make the timeline the entire interface either.

Use the AI chat to express intent, the storyboard to understand and control the story, the video preview to evaluate the result, and the timeline for precise editing.

On mobile, those would become separate tabs in the same project; on desktop, they could appear together.

The main thing is that a beginner can generate a documentary without touching the timeline, while an experienced creator can open up the complete edit and control every detail.

That gives you the simplicity of a one-prompt video generator, but the creative control and production quality of an actual video editor.

And I think your strongest selling point would be the motion-graphics quality—not just the ability to turn a prompt into a video. That’s what makes this concept different from the stock-footage-heavy tools we compared earlier.
