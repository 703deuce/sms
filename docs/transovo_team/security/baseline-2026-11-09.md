## Executive summary — top 5 risks

1. **A Supabase service_role key was committed to git and remains in the history of this now-public repository.** File `.transovo-e2e-supabase.env` (added in `8a100dbc2de0`, removed from the tree in `ab99aec8f45d` on 2026-10-27) contained `SUPABASE_SERVICE_ROLE_KEY` in the `sb_s` secret format. `docs/clips/BLOCKED.md` already tracks this as BLK-SEC-001 but describes a “private-repo commit.” The repository is public, and GitHub secret scanning is disabled. Anyone who can read history can use a service_role key to bypass row-level security. Rotation status is unverified from this review.

2. **The monolith session cookie is unsigned JSON.** `src/lib/auth.ts` `encodeSession` / `getSession` store `userId`, `email`, `name`, and `isAdmin` as `encodeURIComponent(JSON.stringify(...))` in the `transovo_session` cookie, with no HMAC or signature. A caller who can set the `Cookie` header can impersonate any user, including an admin.

3. **`new-app` API routes do not authenticate callers or isolate tenants.** `resolveWorkspaceId()` pins a single env or first-created workspace for every request. `requireSession()` invents a dev user. Classification of all 252 `new-app/app/api/**/route.ts` files at this SHA: 163 use the workspace-pin / fake-session pattern, 29 use only `assertDevApiAccess` (a no-op when `TRANSOVO_DEV_API_KEY` is unset), 37 have no recognized auth helper, 16 use worker/webhook signatures, and only 1 route (`t2v/voices/clone`) requires `getAuthenticatedUserId`. Comments in code say product auth has not shipped. Web deploys automatically from `master`.

4. **Checked-in Supabase schema enables no RLS and defines no policies.** `supabase/schema.sql`, `bootstrap.sql`, and `fresh-install.sql` each define 155 tables, with 0 `ENABLE ROW LEVEL SECURITY` and 0 `CREATE POLICY`. Combined with a leaked service_role key (and a public anon key pattern), this is a full-database exposure if those grants exist on the hosted project. Live GRANT state was not inspected (needs verification).

5. **The root app pins Next.js 16.2.12, which is affected by multiple unauthenticated RCE advisories fixed in 16.4.1.** `new-app` is on 16.4.3, which is still behind the November 2026 release (16.4.5). Dependabot alerts, vulnerability alerts, and secret scanning are disabled on the public repo, so these would not surface automatically.
