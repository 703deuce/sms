## 5. Technical requirements
5.1 Engine: eligible-contact selection, auto next-call progression, durable session state, pause/resume/stop, retry timing, daily + total attempt limits, ring timeout, exclusions, disposition requirements, ownership, duplicate prevention, disconnected-browser handling, concurrency control + idempotency. No duplicate outbound calls from duplicate webhooks, double-clicks, refresh, or repeated commands.
5.2 Eligibility (single authoritative implementation shared by manual + auto): contact still in campaign; valid number; not suppressed/DNC; attempts remain; retry delay elapsed; calling window open; no conflicting live attempt; campaign active; rep authorized.
5.3 Telnyx: outbound origination, browser agent leg, correct caller ID, correct connection state, deduped webhooks, hangups reflected, recordings associated correctly, usage tracked accurately, call can't roll into next contact after session termination. Investigate Telnyx AMD and premium iOS screening detection, event timing, extra costs.
5.4 Screening: verified detection/classification first: live human, voicemail/machine, Apple screening, Google/other when reliably identifiable, IVR, fax, uncertain. Where verified, truthful prerecorded intro + prompt rep participation. Never count a connected screening assistant as a successful human conversation. Avoid excessive silence when a real human answers.
5.5 Recordings + AI notes: reuse existing transcription/summarization; transcript, concise summary, notes, suggested follow-ups, tied to correct contact/attempt/session/campaign. No separate CRM required.
5.6 CRM: use existing connected providers; test contact import, CRM-backed lists, call writeback, dispositions, notes, callbacks/follow-ups, duplicate handling, failed sync, reconnect.
5.7 Minutes/usage: track outbound PSTN minutes, browser/media costs, extra legs, usage by rep/workspace/campaign, included allowances, overage; don't assume equal cost per call; no placeholder totals; keep existing billing safeguards.
